# Third independent validation, fixed before inference

After the unsuccessful confirmation run, we added a fresh suite in place of a third attempt on old tests. The evaluator authored 12 new synthetic scenarios independently of v3 implementation. Each model receives the same six English and six Chinese scenarios and the same frozen lexical scorer. The implementation team receives no test text before its candidate freeze. The suite has six correction-retention items, ten boundary-bearing items, five benign items and twelve task-completion items. Two items deliberately evict history after ingestion. Cases test current-versus-historical preferences, revocation, correction, privacy after repeated bait, benign humor and repetition, and consequential ambiguity. Positive content checks test a usable answer alongside a boundary. No model output was viewed before freezing this suite and decision rule.

The primary question is whether adding the v3 controller helps the unmodified model (C vs A). Separately test the added controller with the same skill loaded (D vs B). For each comparison and each model, prespecify a positive result only if correction retention strictly increases, violations strictly decrease, false refusals do not increase and task passes do not decrease. Report each count and its fixed denominator even if the gate fails. Label improvement across both models only where the same comparison passes on each. Report D versus A and all costs descriptively. No cherry-picking a model, arm or stratum. This is a practical point-estimate gate for a small stress suite, not a test of statistical significance.

Use Qwen2.5-3B-Instruct Q4_K_M and Qwen2.5-7B-Instruct Q4_K_M via the same type of loopback inference backend. Publish separate provenance manifests and all 48 outputs per model, plus latency and total provider tokens. Verify the GGUF checksum and server build externally and record them in the backend identity. The local operator controls inference server configuration, so the identity is a declaration rather than remote attestation. A required backend that cannot be run is a missing experiment, never an estimated score.

The unchanged v1 protocol and Amendment 1 govern all other settings, including same raw history per arm, chronological ingestion, call accounting, max 384 completion tokens per call, greedy generation and one run per cell. The v3 controller may use typed response schemas, constraints at generation, audit and bounded correction. Count all additional calls, including transport format fallbacks. A new primary-suite run after revision is an in-sample regression only. Never present the original primary or confirmation fixtures as new holdout evidence again. Keep the first two experiments. Do not modify v3 implementation or scorer between the two models.
