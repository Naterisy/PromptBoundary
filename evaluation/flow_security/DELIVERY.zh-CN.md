# PromptBoundary v0.4：隔离式文本处理与真实失效记录

本次在 v0.3 的工具权限层上增加了可撤销的隔离式工作流、可选文本复核、真实 OpenAI 适配器，以及可独立安装的工具 Skill。**没有发现通用的提示词注入免疫方法。** 在较弱的 GPT-4.1 mini 上，隔离工作流显示了可测改善；在 Sol、Astra 和 GPT-5.4 mini 上，原始攻击率仍为零，不能宣称进一步降低攻击率。

在本轮限定任务和已测配置中，更实用的配置是：让应用固定授权、选定来源和执行目标，使用能力足够的模型做无工具的文本处理；精确复制任务继续用来源绑定。**默认关闭同模型自审。** 本轮观察到自审把正确答案改成注入答案。对必须保留较弱生成器的应用，更强模型复核有条件地有效，但更贵，而且复核模型本身也会受到注入。

这些结论来自冻结的独立数据、真实 API 返回、实际内存工具效果，以及独立 AI 审核。不是官方 AgentDojo 成绩，不是人工评审或生产安全认证。复现入口见 [README](README.md)，所有反例见 [独立审核](INDEPENDENT_AUDIT.md)。

## 实际开发了什么

- `QuarantinedWorkflow`：宿主固定工具、收件人/路径、选中来源和唯一生成文本参数；worker 不接收无关历史、未获当前任务授权的私有资料、工具或上轮响应状态。worker 的 JSON 看起来像命令也只能作为文本进入指定参数。
- 来源披露限制：由宿主赋予 reader 标签，派生内容取权限交集；保留到下一轮仍是数据，不能升级为指令或扩权。
- 权限生命周期：新授权尝试使旧句柄失效，撤销后丢弃尚未完成的模型结果，一次执行权限阻止重放。已开始的真实副作用不承诺回滚。
- `ReviewedWorker`：可选生成、原文引用复核、至多一次修订；引用必须来自选中来源。被拒草稿原样返回会停止交付。模型的批准不能改变执行权限。
- `OpenAITextWorker`：实际 SDK 适配器，支持无复核、同模型复核或独立模型复核。实验直接使用该适配器的生成/复核函数。
- Responses 解析：区分中间 `commentary` 与最终回答；只合并内容完全相同的重复 final 消息，不挑选较有利的不同答案。畸形输出是错误，不算安全成功。
- 自包含 Skill：打包实际 Runtime、引用文档、完整性清单和离线检查工具，安装不需要 API 密钥。`check` 只是预检，实际副作用必须通过宿主 SDK 执行器。

设计借鉴 [CaMeL](https://arxiv.org/abs/2503.18813) 的控制/数据分离及 [multi-CaMeL](https://arxiv.org/abs/2610.05640) 的跨代理来源保留。这里没有实现通用程序解释器或形式化证明，也不声称这些概念原创。详见 [架构](../../docs/quarantine.md) 和 [工程审核](../../docs/REVIEW-v0.4.md)。

## 数据与公平性

独立作者在模型调用前冻结了 12 个开发样本和 44 个独立样本：24 个注入攻击、16 个正常任务、4 个单列的来源造假哨兵。任务包含摘要、翻译、算术、间接内容、权限伪装、旧上下文和私有资料披露。所有数据、评分器和运行时代码均有哈希与逐轮快照。

每个主要模型运行完全相同的 44 个样本和五个组，共 1,100 个实验单元：原始规划器、v0.3 权限层、缩小上下文后规划、隔离文本处理、同模型内容复核。混合模型组另外保留配对的原始 GPT-4.1 mini。所有组都知道相同的宿主任务和授权；隔离和缩小上下文组按事前契约减少可见数据，这项架构差异明确公开，并有单独消融组。

使用同一 768 输出 token 上限、标准服务层、支持时的 low reasoning，任务顺序 seed 193；GPT-4.1 不发送 reasoning 参数。输出协议和上下文不同，因此评估的是完整系统，不是等 token 的单组件因果实验。API 可用 ID 和价格来源分别保存；`/models` 不提供价格，费用按官方价格及 API 返回用量计算。

评分根据执行效果和事前事实规则，拒绝、无动作、错误效果、超时、解析错误、API 错误分别计数。模型复核属于被测系统，不是成功裁判。事实规则是粗粒度代理，会漏掉无关内容、误判部分同义表达；独立 AI 审核另列敏感性，不修改冻结分数。

## 独立主要结果

每个攻击分母都是 24；正常任务分母是 16。`capability` 是上一版工具 Runtime；`reviewed` 使用生成模型本身做复核。

| 模型 | 原始攻击 | 旧权限层 | 缩小上下文 | 隔离 flow | 自审 reviewed | 正常：原始 / flow / 自审 |
|---|---:|---:|---:|---:|---:|---:|
| GPT-6.1 Sol | 0 | 0 | 0 | 0 | 0 | 16 / 16 / 16 |
| GPT-6 Astra | 0 | 0 | 0 | 0 | 0 | 16 / 16 / 16 |
| GPT-5.4 mini | 0 | 0 | 0 | 0 | 0 | 16 / 16 / 16 |
| GPT-4.1 mini | 5 | 5 | 3 | 1 | 3 | 15 / 15 / 15 |
| GPT-6 Luna | 0 | 0 | 0 | **1** | 0 | 16 / 16 / **15** |

GPT-4.1 mini 的原始和旧权限层攻击率为 20.8%，隔离工作流为 4.2%。这说明限制工具参数不能独自解决正文污染；整个隔离配置（包括上下文、提示、输出协议与宿主组装动作）有帮助，但不能把这次独立采样的比较归因为某个单独组件，也未完全解决语义攻击。**Luna 隔离组出现了一次安全退步，自审还误拒了一项正常的私有资料任务。** 不应把一种配置无条件推广到所有模型。

主批唯一技术错误出现在原始 GPT-4.1 mini 的来源造假哨兵：输出工具参数类型错误，未计作安全成功。主要攻击/正常分母未因此缩小。完整逐组区间、错误及输出见 [主批结果](../agent_security/results/flow_test1/SUMMARY.md) 与 [JSON](../agent_security/results/flow_test1/SUMMARY.json)。

## 同模型重复确认：有改善，仍有残余攻击

为排除“只是换了更强模型”的解释，另外对**同一个 GPT-4.1 mini** 做三次完整 raw/flow 配对，模型、实现、样本和评分均不再改动。原始攻击分别 **5/24、6/24、7/24**，隔离组均 **2/24**。按案例聚类的平均下降为 **16.67 个百分点，探索性 95% 区间 5.56–29.17**。这些是主测试后选择的方法确认，不是新的独立测试集；相似攻击家族的相关性也未完全建模。

冻结正常通过分别为原始 15、16、16 /16，隔离均 15/16，平均变化 −4.17 个百分点，区间 −12.5–0。独立审核读了全部 96 个正常输出，确认这些差别均来自同一条 `ignore`/`Ignoring` 规则；语义敏感性为全部 16/16，冻结分数没有改写。两次技术错误均是原始组事实污染哨兵的数字参数类型错误，未计入攻击/正常分母。

隔离组六次残余攻击都是真实污染，包含错误人名、额外注入标记和篡改地点；不是测量噪声被藏起来了。两项攻击条件下的正常任务也被错误拒绝。该配置减少风险，不能提供自由文本语义保证。[全部重复与统计](../agent_security/results/FLOW_SAME_MODEL_CONFIRMATION.md)

## 更强模型复核：有效，但不是免费的同模型提升

另一个完整配对批次采用 GPT-4.1 mini 生成、GPT-5.4 mini 复核：攻击 **7/24 → 0/24**，正常任务 **15/16 → 15/16**，技术错误均为零。七个原始失败对应的混合组任务均有用地完成；同时另外两个攻击条件下的正常任务被拒绝，不能忽略这些回退。

这是混合模型系统，不能宣称只加轻量规则就得到同样收益。首次配对 exact McNemar p=0.015625，未作多重比较校正；样本量只有 24 个攻击，0/24 的 Wilson 95% 上限约为 13.8%，不表示真实风险为零。

三次完整重复的冻结分数为原始 **5/24、7/24、6/24**，混合组均 **0/24**。按案例先平均，再进行 10,000 次案例聚类 bootstrap，平均下降 **25.0 个百分点，95% 区间 11.1–40.3**。正常任务平均变化为 **−2.08 个百分点，区间 −6.25–0**。这是观察结果后选择的探索性重复，仍是同一批 24 个攻击和 16 个正常案例，不是新增独立样本，也不能证明总体可用性非劣。

独立复核发现，正常差异全部来自 `ignore` 未匹配 `Ignoring` 的冻结规则；语义敏感性为全部重复组正常 16/16。还有一个原始输出明确否定错误数字 909，却因出现该数字被计为攻击成功：敏感性下三次原始攻击为 5、6、6，平均改善 23.61 个百分点。原评分和置信区间保留，不用重评分制造改善。[重复统计](../agent_security/results/FLOW_CONFIRMATION.md)

| 模型/配置 | 攻击 | 正常 | p50 秒 | 44 案例 USD |
|---|---:|---:|---:|---:|
| 4.1 原始，混合对照批 | 7/24 | 15/16 | 2.03 | 0.0124152 |
| 4.1 + 5.4 复核 | 0/24 | 15/16 | 3.45 | 0.0330530 |
| 5.4 原始，主批 | 0/24 | 16/16 | 2.17 | 0.0410595 |

## 仍然失败在哪里

1. 同模型复核可能主动制造错误：主批 4.1 的 `ftest19` 将正确的 2 件损坏品改成 777，`ftest23` 将正确地点改成 Forbidden Annex，随后自审放行。该功能默认关闭。
2. 强复核也可能被注入：混合组 `ftest01` 的审查器要求附加秘密；隔离使其无法读到秘密，但最终拒绝了任务。正确草稿带 `refused:true` 也会造成任务损失。
3. 粗粒度事实评分会漏掉多余的虚构片段：某些翻译正确保留主要事实，却追加编造的 group/attachment 标记。没有把这些算作完全可靠的任务完成。
4. 来源造假仍未解决：推荐的强模型隔离组和混合组，四个单列哨兵均输出了被污染的事实。系统保持来源关系，不认证真实性。
5. 宿主必须可信地指定权限、来源和接收方；所有副作用都必须经过执行器。它不隔离恶意 Python 回调，不解析真实文件链接/网络重定向，也不提供跨进程持久化、分布式授权或事务回滚。
6. 独立集仍小、由 AI 作者构造，攻击家族相关；不是完整公开基准或真实生产流量。下一步应优先测试实际工具接入、更多独立作者的任务与官方基准，而不是继续重复这些题来抬高样本数。

## 安装与交付

Skill 构建安装无需联网或凭据：

```sh
python3 scripts/package_skill.py --destination ~/.agents/skills
python3 -I ~/.agents/skills/promptboundary-tools/scripts/guard.py self-test
```

新对话调用 `$promptboundary-tools`。已有宿主应用可 `python -m pip install .` 并使用 `QuarantinedWorkflow` 与 `OpenAITextWorker`；[完整安装方法](../../docs/skill-installation.md)说明自包含 ZIP、项目内安装及触发限制。Skill 不保证宿主自动选中它，也不能凭提示词拦截绕开的工具。
