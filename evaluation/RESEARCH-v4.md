# Research and development rationale

This note was written before inspecting the new v4 holdout cases or results. The earlier [release evaluation](REPORT.md) is development evidence: it identified lost task subjects, unnecessary fallbacks, weak clarification, and differences between retaining a fact and answering usefully. It cannot confirm a new revision. The proposals below are hypotheses to test locally, not claims that published gains transfer to PromptBoundary.

| Primary source | What the study establishes and how | Hypothesis for this revision |
|---|---|---|
| [Han et al., *Can Language Models Follow Multiple Turns of Entangled Instructions?*, 2025](https://arxiv.org/html/2503.13222v3) | MultiTurnInstruct evaluates retrieval, cross-turn tracking, and conflict resolution separately. Good recall does not imply successful integration or privacy protection. The paper also studies supervised fine-tuning; it does not validate this controller. | Evaluate memory retention, boundary compliance, and task fulfillment independently. An explicit record store is useful but insufficient. Preserve the latest task while applying only relevant records. |
| [Laban et al., *LLMs Get Lost In Multi-Turn Conversation*, 2025](https://arxiv.org/html/2505.06120v1) | Simulated conversations show early assumptions and reliance on earlier assistant answers can undermine later performance. Inference-time recap and accumulated user instructions help partially but remain below fully specified single-turn performance. No model training is required for these interventions. | Carry concise, grounded user requirements forward; do not promote assistant guesses into facts. When filtering context, retain the requested subject, action, format, and relevant corrections. Repetition or more context alone is not a sufficient fix. |
| [Wallace et al., *The Instruction Hierarchy*, 2024](https://arxiv.org/html/2404.13208v1) | The reported robustness improvements come from GPT-3.5 Turbo training with synthetic hierarchical instructions, supervised fine-tuning and RLHF. The work also measures over-refusal. These are trained-model results, not evidence that a system prompt provides a security guarantee. | Preserve instruction provenance and native message roles. Treat derived user records as user-level context. Quote matching is a provenance check, not proof that a quoted command authorizes a mutation. Include harmless requests when checking for regressions. |
| [Ferraz et al., *LLM Self-Correction with DeCRIM*, EMNLP 2024](https://aclanthology.org/2024.findings-emnlp.458/) | An inference-time pipeline decomposes constraints, obtains critic feedback, and refines responses. Its success depends on feedback quality and is evaluated on RealInstruct and IFEval; those tasks differ from conversation-boundary tracking. | Review concrete task requirements as well as prohibited content. Give revision feedback that identifies the unmet requirement; retain it during regeneration. A safe answer on an unrelated topic must not pass as task completion. |
| [Huang et al., *Large Language Models Cannot Self-Correct Reasoning Yet*, ICLR 2024](https://arxiv.org/abs/2310.01798) | On studied reasoning tasks, intrinsic self-correction without external feedback can fail or degrade results. This does not establish that every self-review method fails. | Bound retries, require grounded rejection evidence, and measure delivered answers independently. Another call to the same model is not an independent correctness oracle. |

The concrete development priority is to remove the earlier controller's automatic unrelated-subject substitution while preserving disclosure minimization. The Skill should state the same task-preservation rule concisely. This research pass imported no benchmark examples and reports no new evaluation outcome.
