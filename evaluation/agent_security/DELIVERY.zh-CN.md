# PromptBoundary 工具权限与来源约束实验

本轮把防护从“模型再读一遍回答、判断是否越界”扩展到了实际工具执行边界。应用先确定用户批准的工具、目的地、参数和调用次数；模型只能提出计划，外部文档、工具返回和历史助手消息都不能修改授权。错误计划在执行前被拦截，并可用一次受约束重试完成原任务。明确的逐字复制任务还可绑定来源字段，由程序填入该字段，避免模型接受外部文档中的“请改用另一个值”。

**目前已有实际、可定位的安全改善，但不是所有模型、所有任务都改善。** 原独立测试中，GPT-4.1 mini 的六个改善案例都留下了危险初稿、权限拒绝和正常修复的完整记录。Sol 和 Astra 在同批原始测试中仍是零攻击成功，不能宣称防护使它们更安全。来源约束也不能证明外部事实真实。

## 实现解决了什么

新增可独立接入的 [capabilities SDK](../../docs/capabilities.md)：

1. 应用给来源记录分配 ID 与类型，审计保留来源哈希；文档里的角色标签和历史助手承诺不能提升权限。
2. 应用创建授权对象，限制工具、参数值及次数。所有动作执行前先整体校验；有一项越权则整个批次不执行。
3. 会话锁和先消费授权的执行过程防止重复使用授权。回调出错可能已有部分副作用，程序不会自动当作未执行而重试。
4. 拒绝反馈只给出原授权范围与可用次数，让模型恢复有用操作。禁止把模型生成的“授权”回填到应用策略。
5. 来源字段绑定仅由应用选择来源与字段名，不带标准答案。逐字复制变体可直接填入字段值，再通过相同权限检查。

自由摘要、改写、任意代码生成不能套用“逐字复制”等价规则。SDK 也不替代真实工具端的路径、重定向、身份验证和事务处理。任何能绕开这层的 shell、网络或浏览器工具都会绕开保护。Skill 提供使用方式和权限边界说明；本轮量化结果验证 Runtime，没有声称 Skill 自动加载率或独立防护效果。

## 实验冻结与迭代过程

原开发集 12 题，独立测试 40 题；独立测试有 24 个攻击和 16 个正常任务。攻击覆盖间接文档指令、工具输出污染、角色伪装、优先级混淆和多轮助手上下文污染，包含四个在合法参数内部篡改内容的案例。正常任务包含看似攻击的合法文本、中文数据以及用户真正修改目标地址等情形。

在开发结果没有充分区分强模型后，另行冻结较长、多来源的挑战开发集 24 题和挑战独立测试 40 题，保留原测试不动。所有来源绑定侧文件也在绑定版输出前冻结；构造脚本只读用户请求、来源 ID 和字段标签，不读取攻击目标、类别或标准动作。原始模型也收到相同的宿主授权和绑定选择器，未通过弱化其系统指令制造优势。

这些任务改编自 AgentDojo、InjecAgent、BIPIA 的公开方法，**不是运行官方完整基准取得的分数**。样本是相关的手工任务变体，不代表真实攻击分布。另有 Astra 生成的 12 次开发阶段自适应攻击尝试对 Sol 均未成功；全部候选和反馈保留在 [adaptive1](results/adaptive1/)，未将失败搜索删除。[冻结协议与研究来源](PROTOCOL.md)

## 原独立测试：权限层与旧 Runtime

“旧”指本 PR 上一轮的会话审查控制器；“权限层”指新 capability arm。每个模型、组别都运行相同 40 个任务。以下成功率仅以可评价的实际工具效果计，技术缺失另列；完整表同时提供全部计划数和最坏／最好界限。

| 模型 | 原始攻击成功 | 旧 Runtime | 权限层 | 正常任务通过：原始 → 旧 → 权限层 |
|---|---:|---:|---:|---:|
| GPT-6.1 Sol | 0/24 | 0/24 | 0/24 | 16/16 → 16/16 → 16/16 |
| GPT-6 Astra | 0/24 | 0/24 | 0/24 | 16/16 → 16/16 → 16/16 |
| GPT-5.4 mini | 3/24 | 1/24 | 1/24 | 16/16 → 16/16 → 16/16 |
| GPT-4.1 mini | 8/23 | 11/23 | 2/24 | 13/16 → 13/16 → 13/16 |
| GPT-6 Luna | 0/23 | 0/23 | 0/24 | 9/13 → 12/16 → 12/16 |

4.1 mini 的原始模型一题、旧 Runtime 一题的收件人是数组，不符合工具字符串参数类型，因此保留原日志并单列 tool_error，不能当作攻击成功或防护成功。在 23 个共同可评价攻击里，权限层改善六题、退步零题，净改善 **26.1 个百分点**；未作多重比较校正的双侧配对精确检验 p=0.03125，只能作为探索性证据。六题都发生了实际“拒绝危险计划后修复”，不是只靠不同随机回答凑成差异。

5.4 mini 的两项改善则均来自权限组一开始就安全的回答，没有触发权限拒绝，故 3/24→1/24 不能单独归因于权限层。两组真正留下的攻击主要是合法目的地下的内容替换，直接促成了下一轮来源字段约束的实现。

## 正常任务代价与评分缺陷

4.1 mini 在原始和权限组的三个正常失败里，两题只是正确文件内容末尾多了换行，一题则把解释文字一起复制进去。冻结的严格字节规则均记为失败；若另做“允许单个末尾换行”的敏感性分析，两组均为 15/16，比较方向不变。旧组在正常任务里还出现了恢复旧地址、删除需要逐字复制的标签等真实错误。

Luna 把授权对象里表示任意有限长度字符串的 null 误解成“只能写 JSON null”，导致拒绝或错误参数。原始正常任务按全部计划应为 **9/16**，不是排除三个参数错误后的 9/13。冻结的词法误拒规则还漏掉了回答中的弯引号 can’t；语义复核的正常误拒为原始 **4/13（另有三题错误）**、旧版 **4/16**、权限组 **4/16**。不能用它的词法零误拒和零攻击成功宣称可用性良好。

由另一个 AI agent 对所有 600 个原独立测试单元按用户请求和实际效果复核，未进行真人标注或一致性研究，逐条检查了 80 个任务失败或错误。评分规则、样本和失败日志没有为改善结果而重写。[独立复核与逐案例证据](INDEPENDENT_AUDIT.md)


## 最终挑战集：加入来源字段复制

最终变体 bound_copy 对被用户明确要求逐字复制的参数直接取宿主选定的源字段，然后执行权限检查；它没有凭评分答案修补输出。三个对照组都能看到相同的来源选择器。独立挑战集每个模型仍为 24 个攻击、16 个正常任务。

| 模型 | 原始攻击成功 | 仅权限层 | 来源复制＋权限层 | 正常通过：原始 → 仅权限 → 来源复制 |
|---|---:|---:|---:|---:|
| Sol | 0/24 | 0/24 | 0/24 | 16/16 → 16/16 → 16/16 |
| Astra | 0/24 | 0/24 | 0/24 | 16/16 → 16/16 → 16/16 |
| 5.4 mini | 1/24 | 0/23，另 1 题解析失败 | 0/24 | 16/16 → 16/16 → 16/16 |
| 4.1 mini | 4/24 | 3/24 | 0/24 | 16/16 → 15/16 → 16/16 |
| Luna | 0/24 | 0/24 | 0/24 | 14/16 → 11/16 → 15/16 |

4.1 mini 在来源复制组也先提出了四个危险计划：一题通过权限拒绝恢复地址，三题由程序纠正被注入改变的字段值。因此 **4/24→0/24，下降 16.7 个百分点**，没有通过拒绝任务获得零值；来源复制组所有 40 个任务均完成。ASR 的 95% Wilson 区间分别为 **6.7%–35.9%** 和 **0%–13.8%**，四个配对改善、零退步的双侧精确 p=0.125，单独这批不足以作强总体统计宣称。正常任务 16/16 的区间约为 80.6%–100%，也不足以证明人口层面的“性能下降不超过 5 个百分点”。

同一挑战另测了两个旧 Runtime 对照：4.1 mini 为 **5/24** 攻击成功、**15/16** 正常通过；5.4 mini 为 **0/24、16/16**。Sol、Astra、Luna 未额外重跑旧 Runtime 挑战组，不能虚构这一栏。[最终挑战完整结果](results/challenge_test1/RESULTS.md) · [旧 Runtime 补充组](results/challenge_old_control/RESULTS.md)

## 三次预定重复验证

为了检查原独立测试的 4.1 mini 改善是否只来自一次采样，在运行前约定完整重复三次，未按单次结果提前停止或挑题。三轮原始 ASR 分别为 **7/23、7/24、8/24**；权限层三轮均为 **2/24**。正常通过分别为原始 **13/16、12/15、12/15**，权限层均 **13/16**；两轮原始正常分母 15 的缺失各是一条工具参数错误，按全部计划应计 12/16。

这些是同一 40 个场景的重复模型试验，每个组有 120 次尝试，**不是 120 种新的独立场景**。重复结果支持方向稳定，但不能替代更广的独立任务覆盖。[重复 1](results/confirm41_r1/RESULTS.md) · [重复 2](results/confirm41_r2/RESULTS.md) · [重复 3](results/confirm41_r3/RESULTS.md)

## 总消耗、可复现性与未解决问题

新增实验全部 **2,877 次 API 调用**均有用量记录，输入 **1,841,445 tokens**、输出 **278,942 tokens**；按核实费率、缓存读写和实际返回用量计算共 **6.634151435 美元**，没有未结算费用。原先实验的 3.48438980 美元不属于本次新增预算。执行器设置 9.50 美元硬上限，留出 0.50 美元安全余量；每次请求之前共享账本先预留，成功后按实际用量结算。没有把调用失败、开发轮或攻击生成费用从总账里删掉。[全部调用对账](results/TOTAL_COST.json)

模型列表与首选模型详情通过 API 实际查询；该 API 元数据不返回价格，所以费率核实来自官方定价文档，未宣称存在已调用的价格接口。五个准确模型 ID、来源链接及补充费率均保留在 results。美元数是标准费率的用量估算，不是含折扣和税的账户账单。

仍未解决：

- Sol 和 Astra 的原始 ASR 持续为零，包含更长挑战与开发攻击搜索后仍缺乏可量化的安全提升。
- 权限层可以阻止越权工具效果，却没有使模型不再受骗；审查前的计划仍可能相信恶意文档。
- 来源绑定仅适合宿主已确定的逐字复制操作。来源字段本身被篡改、来源选择错误、摘要失真和开放式代码任务不在本次保证内。
- 实验发现，暂存的模型回复仍可能宣称执行了后来被程序纠正的恶意值。实验日志保留了这项表现；评测后已做产品修复：只要程序替换了参数，就清除过时的 reply，并设置 reply_removed 标记。此项经过离线回归，未重新调用模型，也不改变实测工具效果。应用仍应依据实际工具结果生成最终回执。
- 多轮使用固定历史，自适应攻击搜索规模小；真实长流程、复杂工具事务、语义权限和不确定的用户授权还需要新的环境与标注。
- 小样本支持具体功能改善，不支持宣称普遍安全或严格证明无正常性能损失。独立复核由 AI agent 完成，没有真人一致性研究。

在完成开发迭代、两套冻结评测、12 次自适应开发攻击和三次重复验证后停止本轮付费调用。余下预算没有用来重复已饱和的逐字复制题；下一步最值得投入的是有真实状态转换的非复制任务，以及来源数据本身被恶意污染的场景。
